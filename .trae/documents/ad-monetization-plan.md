# Movie App 广告变现方案

## 概述

项目为纯客户端视频流媒体 APP，视频源为爬取的第三方 CMS API。广告变现完全在客户端播放器层面实现（CSAI），无需控制视频源。

---

## 方案一：信息流广告（推荐先做，改动最小）

### 实现位置

- **首页**：`apps/desktop/src/pages/HomePage.tsx` — MediaGrid 卡片之间插入广告卡片
- **搜索页**：`apps/desktop/src/pages/SearchPage.tsx` — 搜索结果列表中插入广告卡片

### 实现方式

1. 创建广告卡片组件 `AdCard.tsx`，样式与 MediaCard 一致但内容为广告
2. 在 MediaGrid 中按比例（如每 5 个卡片插入 1 个广告）随机插入

### 广告素材

- 初始使用模拟数据（本地静态广告）
- 后续接入广告联盟 SDK 动态获取

### 技术要点

```typescript
// 伪代码：在媒体列表中插入广告
const items = mediaList.flatMap((item, index) => {
  if (index > 0 && index % 5 === 0) {
    return [renderAdCard(), item];
  }
  return [item];
});
```

## 方案二：播放前贴片广告

### 实现位置

- **桌面端**：`apps/desktop/src/components/player/VideoPlayer.tsx`
- **移动端**：`apps/mobile/src/pages/PlayScreen.tsx`

### 实现方式

在 VideoPlayer 组件中增加状态机：

```typescript
type PlayState = 'ad' | 'content';

// 播放流程：
// 1. 用户点击播放 → playState = 'ad'
// 2. 加载广告视频 → 播放广告
// 3. 广告播放完毕(onended) → playState = 'content'
// 4. 加载正片 → 继续播放
```

### 状态机设计

| 状态 | 视频源 | UI 显示 |
|------|--------|---------|
| `ad` | 广告 URL | 显示"广告中..."提示 + 倒计时跳过按钮 |
| `content` | 正片 URL | 正常播放器控制栏 |

### 跳过功能

- 广告播放 5 秒后显示"跳过广告"按钮
- 用户点击跳过直接切换到正片

## 方案三：中插广告（进阶）

### 实现方式

监听视频播放时间，到达预设时间点时暂停正片播放广告：

```typescript
// 监听 currentTime
videoElement.ontimeupdate = () => {
  const currentTime = videoElement.currentTime;
  // 每 10 分钟插入一次广告
  if (currentTime > 0 && Math.floor(currentTime / 600) > lastAdInterval) {
    lastAdInterval = Math.floor(currentTime / 600);
    pauseContent();
    playAd();
  }
};
```

### 插入策略

- 电影：每 10 分钟插入一次
- 电视剧/综艺：每集开头插入一次
- 动漫：每集开头插入一次

### 实现方式

启动应用时显示全屏广告，倒计时结束后自动进入首页：

```typescript
// App.tsx 伪代码
const [showSplashAd, setShowSplashAd] = useState(true);

useEffect(() => {
  const timer = setTimeout(() => {
    setShowSplashAd(false);
  }, 5000); // 5秒后自动跳过
  return () => clearTimeout(timer);
}, []);

if (showSplashAd) {
  return <SplashAd onSkip={() => setShowSplashAd(false)} />;
}
```

## 广告配置动态更新（关键设计）

### 广告链接更换场景分析

| 场景 | 是否需要更换链接 | 是否需要发布新版本 |
|------|------------------|-------------------|
| 广告素材更新 | 是 | 否（通过服务端配置） |
| 广告联盟切换 | 是 | 否（通过配置中心） |
| 广告位ID变更 | 是 | 否（通过配置中心） |
| 广告SDK升级 | 是 | **是**（需重新编译） |
| 广告策略调整 | 是 | 否（通过配置中心） |
| 广告链接失效 | 是 | 否（通过服务端配置） |

### 动态配置方案

```
APP 启动 → 请求配置中心 API → 获取最新广告配置 → 本地缓存 → 实时生效
```

#### 配置中心 API 设计

```typescript
// 广告配置接口响应
interface AdConfig {
  version: string;           // 配置版本号
  updateTime: number;        // 更新时间戳
  adSlots: {
    id: string;              // 广告位ID
    type: 'banner' | 'preroll' | 'midroll' | 'splash';
    enabled: boolean;        // 是否启用
    platform: string;        // 广告联盟平台
    slotId: string;          // 联盟广告位ID
    fallbackUrl?: string;    // 备用广告URL（SDK失败时使用）
    frequency: number;       // 展示频率（秒/次）
    skipAfter: number;       // 跳过时间（秒）
  }[];
}
```

#### 配置更新机制

```typescript
// 伪代码：配置更新逻辑
const [adConfig, setAdConfig] = useState(null);

useEffect(() => {
  // 1. 启动时从本地缓存读取配置
  const cachedConfig = localStorage.getItem('adConfig');
  if (cachedConfig) {
    setAdConfig(JSON.parse(cachedConfig));
  }
  
  // 2. 请求配置中心获取最新配置
  fetch('https://config.example.com/ad-config')
    .then(res => res.json())
    .then(newConfig => {
      // 3. 版本比较，仅更新新版本
      if (newConfig.version !== adConfig?.version) {
        setAdConfig(newConfig);
        localStorage.setItem('adConfig', JSON.stringify(newConfig));
      }
    })
    .catch(() => {
      // 网络失败时使用缓存配置
    });
}, []);
```

#### 配置缓存策略

| 缓存级别 | 存储方式 | 更新时机 |
|----------|----------|----------|
| **内存缓存** | App 运行时 | 每次请求配置中心更新 |
| **本地存储** | localStorage / AsyncStorage | 配置版本变更时 |
| **配置中心** | 服务器数据库 | 运营后台手动更新 |

### 无需发布新版本的更新场景

| 更新内容 | 实现方式 | 生效时间 |
|----------|----------|----------|
| 广告素材 | 服务端返回新 URL | 下次请求配置时 |
| 广告位开关 | 配置中心修改 enabled | 下次请求配置时 |
| 展示频率 | 配置中心修改 frequency | 下次请求配置时 |
| 跳过时间 | 配置中心修改 skipAfter | 下次请求配置时 |
| 广告联盟切换 | 配置中心修改 platform + slotId | 下次请求配置时 |

### 需要发布新版本的场景

| 更新内容 | 原因 | 替代方案 |
|----------|------|----------|
| 广告 SDK 升级 | 需要重新编译 native 代码 | 无，必须发版 |
| 广告逻辑变更 | 需要修改前端代码 | 通过配置中心做条件分支 |
| SDK API 变更 | 需要适配新的 SDK 接口 | 预留扩展接口 |

### 配置中心搭建建议

#### 方案一：自建配置中心（推荐）

```
运营后台 → 数据库 → API 接口 → APP
```

**优点**：完全自主控制，更新灵活

**缺点**：需要开发和维护

#### 方案二：使用云服务配置中心

| 平台 | 说明 |
|------|------|
| **Firebase Remote Config** | 谷歌提供，支持 A/B 测试 |
| **阿里云配置中心** | 国内访问稳定 |
| **腾讯云配置中心** | 微信生态集成 |

#### 方案三：简单静态文件（最小化成本）

```
GitHub/Gitee 托管 JSON 文件 → APP 定时拉取
```

**优点**：零成本，更新方便（直接修改 JSON 文件）

**缺点**：功能简单，无版本管理

## 注意事项

### 合规要求

- 广告内容需符合法律法规
- 需提供"跳过广告"功能
- 广告时长不宜过长（建议 5-15 秒）

### 用户体验

- 广告频率不宜过高（建议每小时不超过 5 次）
- 广告内容应与影视内容相关
- 提供付费去广告选项（未来会员订阅功能）

### 技术优化

- 预加载广告视频以减少等待
- 支持广告缓存以提高加载速度
- 监控广告展示和点击数据

### 推荐发布策略

#### 方案一：官网自分发（成本最低，推荐安全模式）

```
搭建一个官网（技术博客定位）→ 引导至 GitHub/Gitee 下载 → 用户自行安装
```

**优点**：
- 完全自主控制，无需平台审核
- 成本低（只需域名和服务器）
- 更新灵活
- 风险可控（技术定位 + 开源平台托管）

**缺点**：
- 用户信任度低（需要教育用户允许安装未知来源）
- iOS 需要企业签名才能安装

**官网安全定位策略**：

| 策略 | 具体做法 |
|------|----------|
| **技术博客定位** | 官网仅展示技术架构、功能说明、开发日志，不宣传"免费影视"等敏感内容 |
| **GitHub/Gitee 下载引导** | 不直接提供安装包下载，引导用户到 GitHub/Gitee Releases 下载 |
| **APP 不预置视频源** | 默认不内置任何视频源，由用户自行添加配置，类似 VLC/Kodi 的插件模式 |
| **避免敏感词汇** | 官网文案避免使用"免费电影"、"追剧"、"影视"、"VIP"等诱导性词汇 |
| **开源化** | 将代码托管到 GitHub，官网仅作为项目主页和技术文档入口 |

```
官网为主 + 第三方下载站为辅 + 社群推广
```

**优点**：
- 覆盖面广
- 多个渠道引流

**缺点**：
- 管理成本高
- 部分平台可能收费

```
获取正规版权授权 → 申请各大应用商店上架
```

**优点**：
- 正规合法，可持续发展
- 用户信任度高
- 可接入官方支付系统

**缺点**：
- 成本高（版权授权费用）
- 周期长

const currentVersion = '1.0.0';

fetch('https://api.example.com/version')

# 需求留档：播放时短暂显示广告（2026-09-16）

## 原始需求

用户原话：

> 打算在播放时短暂显示广告。
> 1、广告显示在什么位置合适？
> 2、能够接入什么广告可以赚钱？

## 分析结果

### 需求拆解
- 目标形态：「播放时」+「短暂」显示广告，即播放链路内的短时长广告（区别于信息流/开屏）。
- 两个子问题：①广告 UI 位置；②可接入的可盈利广告平台。
- 本次为**方案探讨**，尚未进入实施；实施需用户明确指令。

### 关键语义
- 「播放时短暂广告」对应既有方案文档中的「方案二：播放前贴片广告（preroll）」与「方案三：中插广告（midroll）」。
- 「短暂」= 建议 5~15 秒、可跳过，避免破坏「断点续播/进度记忆」体验铁律。
- 广告逻辑不得干扰现有的：续播进度（currentTime 恢复）、线路切换（handleSourceFail）、画中画（PlayerHost pip 同步）、上下滑切换（移动端）。

### 位置方案（对项目代码的口径）
- **桌面端 VideoPlayer**（`apps/desktop/src/components/player/VideoPlayer.tsx`）：
  - overlays 槽位（`PlayerOverlays`）中新增 AdOverlay，absolute 覆盖视频区（同 skipNotice 的绝对定位，z-20）。
  - 播放前贴片：在 MediaPlayer 上方包一层 ad 状态机（复用现有 loading 遮罩的 z-10/z-20 层级），广告期视频源切换为广告 URL，结束回切正片并 seek 到原进度。
  - 中插：复用现有 `onTimeUpdate`（已驱动 prefetchManager/进度记忆），锚定秒点插入。
- **移动端 PlayScreen**（`apps/mobile/src/pages/PlayScreen.tsx`）：
  - 参考 SkipForwardOverlay/NextEpisodeOverlay 的 absolute + zIndex:30 覆盖层；沉浸/全屏两态都要覆盖。
  - 广告视频可用 expo-video 新建临时 player 或替换 source，结束后恢复原 source + pendingSeekRef 进度。
- **与既有浮层不冲突**的观点：贴片广告应盖过 loading 遮罩但让「跳过广告」按钮可点击；避免与「下一集浮窗」「快进浮窗」同时出现（互斥）。

### 可接入广告平台（赚钱）
| 平台 | 形态 | 适用 | 备注 |
|------|------|------|------|
| AdMob（Google） | 前贴片/插屏视频广告 | iOS/Android RV 视频 | 视频激励广告可无缝插入播放链路；政策要求界面注明「广告」 |
| 穿山甲（字节） | 视频广告/优量汇竞价 | 国内 Android | 收益高但需国内主体资质 |
| 优量汇（腾讯） | 视频广告 | 国内 | 需资质 |
| 亮（国内非SDK方式） | 静态图/网盟 | 「短暂显示」静态横幅 | 免SDK，适合「短暂显示非视频广告」 |

> 注：桌面端（Tauri/WebView）广告平台 SDK 支持弱，多数视频广告 SDK 是移动端原生库；桌面端更适合「静态/横幅/网页 iframe 广告（如 Google AdSense、Adsterra）」或移动端 SDK 的进阶选项。回调需与「跳过/关闭」事件打通以防点击误判。

### 可观测验收清单
- [ ] 广告期出现/正片恢复进程正确（断点续播进度不回退）。
- [ ] 跳过按钮 ≥5s 后可用，点击即回正片。
- [ ] 广告不触发线路失败重试、不污染 prefetchManager。
- [ ] 移动端横竖屏/沉浸/全屏均有广告覆盖层。

### 场景推演
- 断网/线路失败：广告期发生源失败应跳过广告直接进正片重试。
- seek：广告期禁止 seek 正片；中插广告播完后回到原锚点继续。
- 画中画：pip 窗口应跳过广告（或与主窗口同步播广告，二选一需确认）。

### 实施状态（2026-09-16 用户已确认实施）

用户确认的最终方案（逐条对照原始需求确认，无偏离）：

> "在播放中出现浮窗显示广告，浮窗根据广告的大小来灵活变动大小，不影响播放，随机出现，根据广告商的显示时长来显示，广告商没有显示时长要求就固定5秒"；广告内容来源 = 配置驱动的本地模拟广告；实施范围 = 桌面端 + 移动端两端。

#### 确认后的实现要点（对照上述确认）
- 广告形态：**播放中浮窗广告（非贴片/非中插）**，不暂停正片、不打断播放。
- 浮窗尺寸：按广告素材比例等比缩放，随广告大小自适应（限制最大宽度比例防止遮挡观感）。
- 出现时机：播放中**随机出现**（随机时间点触发 + 每次播放最多次数限制 + 两次间最小间隔）。
- 显示时长：取广告配置的 `durationMs`（广告商要求）；未配置则固定 5000ms。
- 广告来源：配置驱动的本地模拟广告（存入 `system_config` 表的 JSON 配置，含示例广告位），无需网络与 SDK。
- 可关闭：浮窗可手动关闭（X）。
- 双端一致：桌面端 `PlayerHost` + 移动端 `PlayScreen` 均实现。

#### 触发调度关键语义
- 状态由「播放进度（currentTime）+ 配置」（真实数据源）驱动，不得用近似语义。
- 会话开始/换集时重置本次播放的广告计数与下次触发点。
- 暂停时浮窗展示计时仅指「出现后到自动消失」，不绑定播放暂停状态。

#### 验收清单（2026-09-16 验证通过）
- [x] 播放中随机出现浮窗、不打断播放、尺寸随广告自适应、按配置时长显示、可关闭 —— 桌面端+移动端均已验证。
- [x] 断点续播/线路切换/画中画进度不受广告影响 —— 调度器与播放器状态独立，无耦合。
- [x] 桌面端与移动端行为一致 —— 两端均通过 OCR 截图验证（浮窗出现/5s自动消失/重现/不遮挡播放字幕）。
- [x] typecheck 通过；移动端双构建部署验证；桌面端验证。

#### 验证中发现并修复的 bug（2026-09-16）
1. **移动端 stale 闭包 bug**：`handleTimeUpdate` 被 setInterval 效应捕获时，闭包中的 `adFloatConfig` 始终为初始 `null`（配置异步加载晚于 effect 安装），导致 `adFloatConfig?.enabled` 恒为 false → 广告永不触发。修复：引入 `adFloatConfigRef`，handleTimeUpdate 读 `adFloatConfigRef.current?.enabled`。
2. **双端 timer 重置 bug**：`onDismissed={() => setActiveAd(null)}` 内联箭头函数在每次渲染时变更引用 → useEffect 依赖 `[ad, onDismissed]` 反复重置 setTimeout → 广告永不自动消失。修复：在 AdFloatOverlay（桌面+移动端）内用 `useRef` 存 onDismissed，useEffect 仅依赖 `[ad]`。

# 需求留档：欢迎页 + 全屏广告启动流程（2026-09-16）

## 原始需求

用户原话：

> 打开APP时先显示一个全屏欢迎页，欢迎页中间是APP的logo，然后显示一个全屏广告，全屏广告持续到首页的追新电影、我的追剧、观看历史、我的收藏的视频图片都读取完后自动消失。桌面端打开APP时不再显示初始化数据库等等那些步骤。

## 分析结果

### 需求拆解
1. **欢迎页**：全屏居中显示 APP logo（短暂展示，过渡到广告）。
2. **全屏广告**：欢迎页之后切换为全屏广告（本地模拟广告，配置驱动）。
3. **自动消失时机**：广告持续到首页四大板块（追新电影、我的追剧、观看历史、我的收藏）**全部数据加载完毕 + 图片渲染完成后**自动消失（非固定时长）。
4. **桌面端改动**：移除现有 `initApp()` 加载过程中显示的「正在加载... + loadingStep」文字，改为静默初始化 + 欢迎页/广告覆盖层。
5. **移动端同步**：同样移除现有 `ActivityIndicator + "正在加载..."` 加载屏，替换为欢迎页 + 广告流程。
6. **范围**：桌面端 + 移动端双端实施。

### 架构方案（跨组件通信）
- **共享状态**（`packages/core` 新增 `splashStore.ts`）：Zustand store，管理 `phase: 'logo' | 'ad' | 'done'` 与 `homeReady: boolean`。
- **启动流程**：
  1. App 初始化（initApp 仍在后台运行）→ 同时显示欢迎页（logo，约 1.5s）。
  2. 欢迎页过渡 → 全屏广告（ads 取自 `playback.adFloat.ads` 配置，取第一条或轮播）。
  3. 主应用（NavigationContainer / BrowserRouter）在广告下方渲染，首页 useEffect 并行加载数据。
  4. 首页所有数据加载完毕 → splashStore.setHomeReady(true) → 广告淡出消失。
- **桌面端**：`MainApp` 始终渲染 `<ThemeProvider><BrowserRouter>` 等路由层，广告层 absolute 覆盖其上。
- **移动端**：`App.tsx` 始终渲染 `<SafeAreaProvider><NavigationContainer>`，广告层 absolute 覆盖其上。

### 首页数据加载追踪
首页四大板块各自在 `useEffect` 中异步加载，需要逐一确认完成：
| 板块 | 桌面端 HomePage 加载 | 移动端 HomeScreen 加载 |
|------|---------------------|----------------------|
| 追新电影 | `useEffect(() => { getProvider().listMedia(...).then(setLatestMedia) }, [])` | `useEffect(() => { ...collectLatest()... }, [])` |
| 我的追剧 | `loadUserUsageTypes()` → favoriteList 按 TV_SERIES 过滤 | `loadUserUsageTypes()` → 同理 |
| 观看历史 | `loadWatchHistory()` | `loadWatchHistory()` |
| 我的收藏 | `loadFavorites()` | `loadFavorites()` |
| 图片渲染 | 依赖 posterImage onLoad 事件或 data-url 加载完成 | 同理 expo-image onLoad |

**完成判定方案**：首页在所有数据 `useEffect` resolve 后调用 `splashStore.setHomeReady(true)`。图片渲染无法逐张追踪（复杂度高），采用「数据加载完毕 + 延迟 800ms」兜底（图片已进入缓存后二次渲染极快）。

### 广告内容来源
- 配置：复用 `system_config` 表 JSON key `playback.adFloat.ads[]`（同现有浮窗/横幅广告配置）。
- 全屏广告取第一条，或从 ads 随机取一条。
- 展示内容：`imageUrl` 全屏铺满（`object-fit: cover`），点击 `linkUrl` 跳转。无图片时显示标题 + 渐变背景。

### 动画
- 欢迎页（logo）：淡入 → 保持 1.5s → 淡出（300ms）。
- 广告：从下方滑入（300ms）→ 展示 → 数据就绪后淡出（400ms）。

### 待确认关键点
1. 欢迎页是否已有确定的 logo 图片资源？（桌面端目前无专用 logo，移动端有 `splash.png`） → **已确认：用 `adaptive-icon.png`（复制到桌面端 public/）**
2. 广告无图片时是否显示纯文字广告，还是跳过全屏广告直接进首页？ → **已确认：显示标题+渐变背景**
3. 欢迎页显示时长（建议 1.5s，或在 initApp 完成后立即切换）？ → **已确认：固定 1.5s 后切换**
4. 首页四大板块是否全部数据未加载完时超时（如 10s）强制消失广告？ → **已确认：需要 10s 超时兜底**

# 需求留档：广告不用配置功能（2026-09-16）

## 原始需求

用户原话：

> 广告不用配置功能

> 背景：上一步为让桌面端显示广告，把 `playback.adFloat`（enabled:true + 两条示例广告）写入了桌面端 DB。用户此句意在否定「广告需要配置」的做法（不逐一依赖 DB 写入/设置项开关），要求广告直接可用。

## 分析结果

### 需求拆解
1. 广告**默认启用**，不再依赖 `playback.adFloat.enabled` 配置项（enabled 恒开启）。
2. 广告素材（ads）**内置在代码**中，不依赖 `system_config` DB 写入（新装用户即可见广告）。
3. 设置页「播放广告」开关：**彻底移除**（双端），广告不可关闭。
4. `systemConfigService.getAdFloatConfig()/setAdFloatConfig()`：**删除**（无调用方）。

### 确认后的实现要点
- `BUILTIN_AD_FLOAT_CONFIG`（packages/core 导出）：`enabled: true`，含两条示例广告（竖版海报位 360×240 + 通栏位 640×300），各消费方直接 import 常量，不异步读 DB。
- 双端设置页 `UsagePreferencesPage/Screen` 移除广告开关卡（整个 Card 删除）。
- 桌面端 PlayerHost / 移动端 PlayScreen：移除 `adConfig`/`adFloatConfig` state，移除 `.enabled` 判断，调度器直接由内置常量构造。
- 桌面端 DB 中已写入的 `playback.adFloat` 记录：无害，保留（不再被读取，成为死数据）。
